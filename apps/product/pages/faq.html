answered honestly.

Every answer below traces to the repository or to facts.json. Where the honest answer is a limitation, the answer states the limitation.

Why do metros differ from each other?

Because their registry entries declare different datasets. The city registry records, per metro, which feed families publish, on which platform (Socrata, ArcGIS, Carto, CKAN), at what cadence, and with which divisions and submarkets. One metro publishes all four families; another publishes fewer. Coverage is stated per metro on /cities — never averaged into a single number.

What does “limited” mean on a feed token?

A struck-through token means the metro's registry entry currently declares no dataset spec for that feed family — the pipeline does not ingest that family there yet. It is a statement about declared sources, not about data quality, and it can change only by changing the registry, never the copy.

How often does each feed refresh?

Refresh cadence is declared per feed in the registry as an interval — the poll cadence of the upstream platform — and surfaced in the coverage matrix and cadence table on /cities, counted from facts.json. Intervals differ across platforms and metros. Signals move at feed cadence: minutes for some feeds, snapshots for others. Cadence is declared, never implied realtime.

Where does the data come from?

Municipal open-data portals. Source-specific producers read Socrata, ArcGIS, Carto, and CKAN endpoints declared in the city registry, preserving each city's field names before normalization. The registry is the contract: if a dataset is not declared there, it does not exist downstream. Every metro page links its exact source contract under “Inspect this metro's source contract.”

How do I run this locally?

The repository README covers it end-to-end in its Quickstart & Local Development section — infrastructure, ingestion producers, stream consumers, the serving API, and the dashboard. Commands are kept in one place, next to the code they run, so they cannot drift from it: README → Quickstart & Local Development.

How does a city get registered?

Through four gates, enforced by the repository rather than by goodwill: declare a registry entry (endpoints, watermark column, divisions, submarkets); project it — facts:export regenerates the site's facts so hand-edited coverage cannot drift; wire it — the dashboard map must show the city, and the interlock gate fails any run where it does not; publish — site pages regenerate from the same facts. A city that skips a gate does not ship. The walkthrough lives on /architecture.

What do the scores NOT mean?

The boundary stated on /methodology applies everywhere. LIMS is not a price forecast — it measures momentum in municipal activity, not transaction prices or returns. It is not a performance claim — no accuracy, precision, or ROI numbers are published anywhere on this site, by policy rather than omission. And the 68/100 panel shown there is an illustrative interface example: only its ingredient weights are the calculator's real defaults.
