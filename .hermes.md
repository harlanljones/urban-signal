# Hermes project rules — Urban Signal

`AGENTS.md` is the operating manual for commands, layout, invariants, and CI. This file adds Hermes-specific session behavior; do not duplicate or override it.

## Session behavior

- Read `AGENTS.md` before editing. Its CI/CD pre-flight is mandatory before ending any task; do not substitute a partial lint/test run.
- For multi-agent work, read `docs/agents/parallel-streams.md` and `docs/agents/spine-manifest.txt` first. Keep work leaf-shaped where possible; spine edits require the interlock gate and stream claim/dispatch conventions.
- A registered city is incomplete until dashboard `METRO_META`, snapshot coverage, res-5 grid coverage, product facts, and the byte-synced static dashboard all include it.
- Preserve data-source boundaries, city wiring, and published dashboard artifacts. Avoid unrelated generated-file churn.
- Use `./dev` to start Hermes in the `urban-signal` profile. Bootstrap with `./dev setup`, validate with `./dev doctor`, and use `./dev -z "prompt"` for one-shot mode. The script configures the repo-local profile and does not modify Hermes' default profile.
- Hook scripts are versioned in `agent-hooks/` and installed to `$HERMES_HOME/agent-hooks/` (default `~/.hermes/agent-hooks/`) by `./dev setup`. The git guard blocks mutating Git commands; ask Harlan to run them or obtain explicit approval.

## Skill routing

Load a skill with `skill_view(name='...')` when the task matches. `./dev` keeps this project's focused skills available; others stay disabled in the repo profile.

| Task | Skill |
|---|---|
| Feature or bug fix | `test-driven-development` — tests first |
| Non-obvious failure | `systematic-debugging` — establish root cause before edits |
| Multi-task approved plan | `subagent-driven-development` — fresh implementer per task, spec and quality review |
| Parallel streams | `subagent-driven-development` plus the repo interlock docs; obey the spine/leaf partition |
| Before committing | `requesting-code-review` — scan, gates, independent review, fix loop |
| Simplifying a completed milestone | `simplify-code` |
| API/Python debugging | `python-debugpy` |
| Dashboard/product UI design or critique | `impeccable`; use `dogfood` for exploratory browser QA |
| Docker/Compose work | `dockerize-web-app` |
| Repo-local Hermes changes | `hermes-repo-devsetup` and `hermes-agent` |
| GitHub PRs, issues, or reviews | `github` |
| Shell scripts targeting Linux and macOS | `shell-portability` |
| Codebase metrics | `codebase-inspection` |
| Validating an unknown design before building | `spike` |
| Substantial autonomous work | `unlazy` — keep going to verified completion |
| Plan interview before implementation | `grill-me` — follow Harlan's explicit invocation and expectations |

Negative controls:

- A small doc wording change does not need a skill.
- A reproducible bug is debugging, not `spike`; use `spike` only to test an uncertain design.
- Do not use parallel agents before reading the stream/interlock rules, even for apparently independent work.
- Do not replace the mandatory full CI/CD pre-flight with `bun run lint`, typecheck, or a subset of tests.

## Hooks

Configured per profile (`$HERMES_HOME/profiles/urban-signal/config.yaml`), with scripts in `$HERMES_HOME/agent-hooks/`:

- `urban-git-guard.sh`: `pre_tool_call` on `terminal|execute_code`, `fail_closed: true`; blocks mutating Git commands.
- `urban-formatter.sh`: `post_tool_call` on `write_file|patch`; runs Ruff on Python files and Prettier/Biome on JS/TS/JSON when installed, otherwise no-ops.
- `urban-evidence.sh`: `post_tool_call` on `terminal`; appends compact command/cwd JSONL evidence under the Hermes hooks directory.
- `urban-inject-git-status.sh`: `pre_llm_call`; injects branch and dirty-file status only inside this repository, matched by its GitHub origin URL.

Hook consent is per profile. If hooks are pending on a fresh machine, approve them at first session start or use Hermes' `--accept-hooks` option.
